# 0.9.3 — 性能优化第二轮(轮 5-6)

日期:2026-09-29 · 主题:在不影响安全性、稳定性、兼容性(红线)的前提下继续性能优化。
完整六轮对比报告:[`note/report/perf/2026-09-29-perf-optimization.md`](../report/perf/2026-09-29-perf-optimization.md)。

## 轮 5:MCP 响应序列化(commit bc0687f)

- **分析**:tools/list 是唯一应答内容恒定的方法(tools 数组启动即固定),每帧却要 `JSON.stringify` 整个对象(852ns/帧)。
- **改动**:启动时预序列化 result 常量,应答模板拼接(67ns/帧);其他方法路径不变。
- **结果**:单帧序列化 ×12.7(确定性微基准);端到端 chunked ×1.11~×1.21、burst 噪声带内不回退。
- **等价保障**:bench-mcp 新增探测断言——两变体 initialize+tools/list+ping 三应答,归一化 serverInfo 版本号后逐字节比对;另附序列化微基准(从真实应答解析出 tools 对象,避免基准内复制定义漂移)。

## 轮 6:watch() 采样节拍对齐(commit 6d36881)

- **分析**:老实现每拍「等请求返回再睡 1s」,串行节拍随接口延迟线性累积(5s 采样 @600ms 接口要 7.1s),样本时刻漂移出 1s 网格。
- **改动**:每秒固定节拍并发发起(`Promise.all` 按发起序收结果);失败回退语义保持,慢失败端点最多滞后一拍、多发个位数并发请求(各有 3s 超时),不影响总时长与结果结构。
- **结果**:slow 7099→4635ms(×1.53)、fast ×1.06、down ×1.00;快/慢画像输出(除 time)逐字段全等,down 回退结构全等。
