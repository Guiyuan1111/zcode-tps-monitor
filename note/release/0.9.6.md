# 0.9.6 — AI 注意力占用优化(轮 9-10)

日期:2026-09-30 · 上一版:0.9.5(文档对齐)

## 背景

前八轮(0.9.1-0.9.4)优化的是运行时耗时;用户提出新目标:**减少插件对 AI 工作的
影响**——即插件注入到模型上下文的全部文本面(每轮注入、会话提示、MCP 工具定义、
技能描述)。红线:安全性、稳定性、兼容性;收尾自测机制的行为契约一字不丢。

## 决策

- **量化先行**:新建 `benchmark/bench-attention.mjs`,以 estTokens 启发式量化四个
  注入面;基线冻结为 `baseline-v0.9.5/`(文本面基线必须取最近版本,运行时基线仍是
  v0.9.0)。
- **轮 9(每轮注入面,最大头)**:注入命令里的完整安装路径随版本变长且占 60+
  字符/轮——hook 首次运行把脚本逐字节复制到 `~/.zcode/token-rate.mjs`,命令缩为
  `node ~/.zcode/token-rate.mjs --turn --current`;指令压缩为三行,五要素守卫保留。
- **轮 10(一次性面)**:机制细节只在每轮注入一处讲解(session-start 只留索引);
  MCP 描述/SKILL 描述去掉重复的机制说明,保留全部触发关键词与参数约束。
- **基准等价口径适配**:注入/描述文本是优化对象本身,逐字节比对不再适用——改为
  「结构逐字节 + 文本语义」:stop 输出仍逐字节;注入钩子校验严格 JSON 结构与非空;
  MCP 归一化描述与帧长后逐字节(帧序/字段序不变);语义守卫由 bench-attention 与
  21 项单测承担。

## 验证

- `node --test` 21/21;bench-attention:perTurn ×2.1、session ×2.46、tools ×1.24、
  skill ×1.95、百轮累计 ×2.09(23,205→11,102 est tok)。
- 运行时回归门 `run-all medium` 六基准全绿,无回退(prompt-submit ×1.036、
  session-start ×0.997)。
- 兼容性:`tokenRateLine:false` 行为不变(空注入、不建副本);MCP 帧序/字段序不变;
  stop 输出逐字节不变;session-start 注入仍为无条件(与基线一致)。
- 事故修复:副本曾命名 `tps-rate.mjs`,与脚本 CLI 守卫(按文件名后缀判定)失配导致
  收尾统计静默无输出——已定名 `token-rate.mjs` 并固化约束(commit 14382f8)。
