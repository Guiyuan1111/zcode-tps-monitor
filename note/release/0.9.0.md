# 0.9.0 发布要点

日期:2026-09-29 · 前置版本:0.8.3 · 主题:**聚焦「回复末尾的本问速率行」,移除大屏,落实分析报告中的高优先级优化**

## 背景与决策

- 用户明确不需要监控大屏,只要「对话结束后带一行本问速率」的核心功能 → 大屏/悬浮条整体移除(0.8.x 仍可用)。
- 其余优化按 `codebase-analyzer/reports/zcode-tps-monitor-2026-09-29_164007/04-ai-substitution.md` 及后续分析执行。

## 改动清单

### 移除
- `plugins/zcode-tps-monitor/dashboard/`(server.mjs / index.html / overlay.ps1)
- `commands/dashboard.md`、doctor 的大屏 PID 探活、全部文档与清单中的大屏描述

### 修复(对应分析编号)
| 编号 | 问题 | 修法 |
|---|---|---|
| A1 | 多窗口并发时收尾自测可能串到其他会话 | 指令命令行内联 `ZCODE_SESSION_ID="<sid>"`,状态文件仅作手动运行兜底 |
| A2 | `tps_watch(30)` 总耗时 ≈30.5s 与 MCP 30s 超时贴线 | `.mcp.json` timeoutMs 30s→60s |
| A3 | 指标接口发完头挂住 body → 调用方永久悬挂 | 超时计时覆盖 `res.json()`(已验证 1200ms 处中止) |
| B1 | `snapshot()` 串行「抓取+CPU 采样」延迟求和 | `Promise.all` 并行 |
| D1 | Node<22.5 时钩子模块加载即崩 | stop.mjs 动态导入;prompt-submit 不再触碰 node:sqlite |
| D2 | SessionStart 只匹配 startup/clear | matcher 增加 resume/compact |
| D4 | doctor PID 探活的 PID 复用误报 | 随大屏移除一并消失 |

### 变更
- C1:不再注入「上一轮·内部背景」行(每轮省约 50 token,结构性消除上轮泄露面);prompt-submit 钩子现已零数据库访问。
- DRY:新增 `hooks/lib.mjs`(writeSessionState/readConfig),状态文件路径支持 `TPS_MONITOR_STATE_FILE` 覆盖。
- 全部指令表面(欢迎语/指令/SKILL/两 README/清单描述)已同步对齐——遵循 v0.8.3 确立的口径一致性纪律。

## 验证
- `node --test` 13/13 全绿(CI 将在三平台 × Node 22/24 复验)
- 钩子冒烟:指令含内联会话 ID、`tokenRateLine:false` → 空注入、慢响应体 1217ms 中止、MCP initialize/tools/list 正常
