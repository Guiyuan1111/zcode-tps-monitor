# 0.9.4 — 性能优化第三轮(轮 7-8)

日期:2026-09-30 · 主题:在不影响安全性、稳定性、兼容性(红线)的前提下继续性能优化。
完整八轮对比报告:[`note/report/perf/2026-09-29-perf-optimization.md`](../report/perf/2026-09-29-perf-optimization.md)。

## 轮 7:SQLite 连接级读取调优(commit 8fdb18e)

- **分析**:原型探针(large 夹具隔离剖析)显示 `mmap_size` 使 SUM 扫描 56.5→14.9ms(×3.8)、窗口查询 73.2→33.0ms(×2.2);`temp_store=MEMORY` 对排序语句再省 ~10%。
- **改动**:`openDb()` 内三条连接级 PRAGMA,try/catch 兜底(不可用环境静默退回默认)。**连接级设置不写库文件**(区别于建索引/ANALYZE 的文件级变更)。
- **只读证明**:bench-token-rate 新增断言——基准全程跑完后夹具库 SHA-256 不变 + 无 `-wal`/`-shm` 旁文件,每次跑基准自动重新验证。
- **结果**(large):queryTurn 174.5→50.6ms(×3.45)、query 96.8→38.5ms(×2.51)。

## 轮 8:免排序聚合取最新行(commit b80774d)

- **分析**:轮 7 后剩余成本中 `latestTurnId`(7.7ms)与全局 fallback(12.4ms)耗在 `ORDER BY completed_at DESC LIMIT 1` 的临时 B-tree 排序上。
- **改动**:MAX() 裸列惯用法(`SELECT turn_id, MAX(completed_at) ...`,SQLite 文档化行为:单 min/max 聚合时裸列取自命中行),免排序;空集返回一行 NULL,与 LIMIT 1 未命中同义。同轮**否决**窗口函数合并方案(实测 45.2ms > 现状两条扫描合计 31.9ms)。
- **结果**(large):latestTurn 7.7→5.1ms、全局 fallback 12.4→6.3ms。
